# Tarkeeb Practice — Project Notes

Web app for practicing i'rab al-Qur'an (إعراب القرآن — tagging each word/morpheme of a Quranic ayah with its grammatical role: فعل، فاعل، مفعول به، مبتدأ، خبر، إنّ وأخواتها...). Student clicks a word (or an attached particle split off from it), picks its role from a list, checks the answer, and gets per-word right/wrong feedback plus a score. Sibling project to `../stock-tracker/` in the same `VibeCode/` directory; built for the user (self-described coding beginner) following that project's conventions.

**Content history:** v1 used generic hand-written beginner/intermediate sentences (not Quranic). Replaced entirely (2026-10-17, user's explicit call) with real ayat and real i'rab, since the user specifically wants Quranic i'rab practice. This was a bigger change than it sounds — see the roles/data-model notes below for why.

**UI language policy (2026-10-17):** App chrome (titles, buttons, instructions, stats, score messages) is **English**. The ayah text, role category labels, and the role labels themselves stay **Arabic** — confirmed explicitly with the user (asked specifically whether role labels like فعل/فاعل should translate too; answer was no, keep them Arabic since picking the correct Arabic term is the actual exercise). One deliberate exception: `SentenceDisplay`'s "no answer" fallback string (`"بلا إجابة"`) stays Arabic too, since it renders inline right next to Arabic role labels in the same RTL-flowing results line — translating only that one fragment would break the visual flow. When adding new chrome text, wrap any embedded Arabic content (surah name, a single word, etc.) in its own `dir="rtl"` span rather than setting `dir="rtl"` on a whole now-English container.

**I'rab/note translations (2026-10-17):** Every `irab` and `note` string in `sentences.ts` now has an `irabEn`/`noteEn` English translation shown alongside it (own `dir="ltr"` line, smaller/muted, below the Arabic). The Arabic stays the source of truth; the English is a teaching aid using standard nahw-to-English terminology (nominative/accusative/genitive for مرفوع/منصوب/مجرور, jussive for مجزوم, construct/iḍāfah for الإضافة, etc. — kept consistent across entries, see the existing translations in `sentences.ts` before inventing new phrasing for the same concept). **Not every word's `irabEn` has been independently fact-checked against a second source the way the original Arabic `irab` was** — it's a direct translation of already-verified Arabic, so treat translation accuracy (not underlying grammar accuracy) as the main risk if something looks off.

## Stack
- Next.js 16.4.2 (App Router, Turbopack), React 19.3.0, TypeScript, Tailwind 4.
- **Newer than stock-tracker's Next 16.2.10** — this version defaults [Cache Components](https://nextjs.org/docs/app/getting-started/caching) to **on**, which requires every `cookies()`/`headers()` read to sit behind a `<Suspense>` boundary (or use `use cache: private`) or the build/dev server errors ("Next.js encountered runtime data during prerendering"). **Deliberately disabled** (`cacheComponents: false` in `next.config.ts`) to keep the simple request-time rendering model stock-tracker uses, since every page here is per-user anyway and doesn't benefit from partial prerendering. If a future Next.js upgrade re-enables this by default, read `node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md` before touching auth code.
- Auth + database: **Supabase** (Auth with Google OAuth + Postgres with Row Level Security), same choice and rationale as stock-tracker (one dashboard instead of three). **This is a separate Supabase project from stock-tracker's** — different `.env.local` values, different Google OAuth redirect URI to register.
- No charting/data-fetching libraries — all practice content is static, versioned TypeScript data (see below), no external API calls at all in the core practice flow.

## Architecture
- `lib/tarkeeb/roles.ts` — 22 grammatical roles (`RoleId` union + `ROLES` array), each with an Arabic `label`, an English `hint`, a Tailwind `color` class string, and a `category: RoleCategory`. The original 12 (فعل، فاعل، مفعول به، مبتدأ، خبر، حرف جر، اسم مجرور، نعت، حرف عطف، ظرف، مضاف إليه، حرف نفي) plus 10 added for Quranic grammar: `inna_sisters`/`inna_subject`/`inna_predicate` (إنّ وأخواتها / اسم إنّ / خبر إنّ), `kana_sisters`/`kana_subject`/`kana_predicate` (كان وأخواتها / اسم كان / خبر كان), `tawkid_particle` (حرف توكيد — e.g. اللام المزحلقة), `exception_particle`/`exception_noun` (أداة استثناء / مستثنى — إلا constructions), `separating_pronoun` (ضمير فصل). Add a new role here first if a future ayah needs one not yet covered (e.g. حال، تمييز، بدل, مفعول مطلق/لأجله/معه weren't needed for the current 10 ayat but will come up eventually) — remember to also assign it a `category`.
  - **`RoleCategory`** (7 values) groups roles the way Arabic grammar is actually taught, exported as `ROLE_CATEGORIES` (ordered, each with an Arabic `label` and an English `labelEn`): `verbal_sentence` (الجملة الفعلية / Verbal Sentence: فعل/فاعل/مفعول به), `nominal_sentence` (الجملة الاسمية / Nominal Sentence: مبتدأ/خبر), `governing_particles` (النواسخ / Governing Particles: all 6 إنّ/كان roles), `genitive_prepositional` (الجر والإضافة / Prepositions & Genitive: حرف جر/اسم مجرور/مضاف إليه), `followers` (التوابع / Modifiers: نعت — only one role today, kept as its own category since more followers like توكيد لفظي/بدل/عطف النسق are likely future additions), `exception` (الاستثناء / Exception: أداة استثناء/مستثنى), `other` (عناصر أخرى / Other — catch-all for particles/elements that didn't fit elsewhere: حرف عطف/حرف نفي/حرف توكيد/ظرف/ضمير فصل). `RolePicker` renders one labeled section per category (Arabic label bold/prominent + English `labelEn` alongside it, smaller/muted), in this order.
- `lib/tarkeeb/sentences.ts` — the ayah bank (`SENTENCES` array), 10 ayat as of this writing across three short surahs (الكوثر ١-٣، الإخلاص ١-٤، العصر ١-٣), each `{ id, text, surah, ayahNumber, difficulty, words: [{ text, role, irab?, irabEn?, joined? }], note?, noteEn? }`. Word order in `words` must match the visual word order in `text` — `SentenceDisplay` renders `words[i]` as the i-th chip.
  - **`joined: true`** fuses a chip to the *previous* one with no gap — used to split an attached morpheme (prefixed و/ف/ب/ل/ك, or a clearly-separable suffixed pronoun like ـك/ـه/ـنا carrying its own role) off from its host word, since one clickable chip can only carry one role. A verb's own person/number agreement marking (و الجماعة etc.) is intentionally **not** split this way — it stays bundled into the verb's single chip, explained in that word's `irab` text instead — the line is "does this morpheme have an independently-teachable grammatical role" (split) vs. "is this just normal verb conjugation" (don't split, see e.g. `آمَنُوا` in asr-3).
  - The optional `irab`/`irabEn` fields hold full i'rab detail (case ending + reason), Arabic + English translation, for a word; surfaced in `ScoreBanner`'s collapsible "I'rab details (optional)" section after checking (each list item shows the Arabic then the English, in its own `dir="ltr"` line). The optional sentence-level `note`/`noteEn` fields are for clause-level relationships that don't belong to any single word (e.g. "الجملة الفعلية ... في محل رفع خبر إنّ", or a word-order inversion explanation) — shown in `ScoreBanner` below the i'rab list, same Arabic-then-English pattern.
  - **Every ayah's i'rab was checked against standard references** (not just recall) before being written — the genuinely contested points (هو in قل هو الله أحد / إن شانئك هو الأبتر, and كفوًا في سورة الإخلاص) were cross-checked via web search against published i'rab rather than guessed. Scholars do legitimately differ on some of these (noted inline in the `irab` text where relevant, e.g. kawthar-3's هو). Treat this as carefully-done but not infallible — it's scripture, worth a knowledgeable second read, not just an LLM's say-so. If you add more ayat, verify the same way rather than trusting recall alone, especially on anything where you sense scholarly disagreement might exist. See the UI language policy note above re: `irabEn`/`noteEn` translation accuracy specifically.
- `lib/tarkeeb/grading.ts` — `gradeAttempt(sentence, studentRoles)`, a pure function (no side effects, nothing to mock) comparing student-picked roles against the sentence's correct roles; `WordResult` carries both `irab` and `irabEn` through to the UI. Unaffected by the `joined`/surah/note additions — still just a flat indexed array under the hood.
- `lib/supabase/{client,server,middleware}.ts`, `proxy.ts`, `lib/dal.ts` (`getUser()` wrapped in `cache()`) — copied verbatim from stock-tracker's proven `@supabase/ssr` pattern.
- `app/actions/auth.ts` (`signInWithGoogle`/`signOut`), `app/auth/callback/route.ts` — same pattern as stock-tracker.
- `app/actions/attempts.ts` — `recordAttempt(sentenceId, correctCount, totalCount)`: **no-ops silently if signed out** (practice doesn't require an account); `getAttempts()` for the progress page. Both independently call `getUser()` per the stock-tracker convention (proxy only does optimistic cookie refresh, every data-touching function re-checks).
- `app/page.tsx` — the practice page. Works whether signed in or not: header shows sign-in/out, main area always renders `<PracticeSession />` regardless of auth state (unlike stock-tracker, which gates the whole page on auth).
- `app/components/PracticeSession.tsx` — client component, the orchestrator. Picks a random sentence **client-side only** (in a `useEffect`, with an `eslint-disable-next-line react-hooks/set-state-in-effect` — intentional: `Math.random()` in SSR would bake a different sentence into the initial HTML than the client picks on hydration, causing a mismatch). Owns `{wordIndex: RoleId}` student-answer state, the active-word-being-tagged index, and the grade result; renders `<AyahReference>` + `<SentenceDisplay>` + `<RolePicker>` + `<ScoreBanner>` + Check/Next buttons. Header shows `Surah {surah} • Ayah {ayahNumber}` (English labels, Arabic surah name wrapped in its own `dir="rtl"` span) instead of a nominal/verbal label.
- `app/components/SentenceDisplay.tsx` — renders the sentence as RTL word-chip buttons (`dir="rtl"`, `font-arabic` class). Spacing is per-chip margin (not a uniform flex `gap`), set to zero before any chip whose `joined` is true, so split-off particles render flush against their host word — verified this still looks right when a joined pair wraps onto a new line on mobile. Chip coloring: gray/unselected → role color once tagged → green/red once checked (with the correct role revealed next to any wrong word).
- `app/components/RolePicker.tsx` — the popover panel (rendered inline below the sentence, not an absolutely-positioned floating tooltip — simpler and works the same on mobile), iterating `ROLE_CATEGORIES` and rendering each as a small heading + its roles' colored chips (`ROLES.filter(r => r.category === category.id)`), instead of one flat 22-chip row.
- `app/components/ScoreBanner.tsx` — "X / Y correct" result banner (English), the collapsible "I'rab details (optional)" section (English toggle label; each `<li>` is the Arabic `irab` line, `dir="rtl"`, with its `irabEn` translation as a smaller muted `dir="ltr"` line underneath when present), and the sentence-level `note`/`noteEn` (same Arabic-then-English pattern) below it.
- `app/components/AyahReference.tsx` — small read-only block showing the full, undivided `sentence.text` above the interactive breakdown, labeled "Full Ayah" (English label, Arabic ayah text in its own `dir="rtl"` paragraph). Always visible (before/after checking); purely presentational, no state.
- `app/progress/page.tsx` — signed-in only (`redirect("/")` otherwise, matching stock-tracker's `stock/[symbol]/page.tsx` pattern), shows `<ProgressStats>` (total attempts, overall accuracy, per-attempt history table) from `getAttempts()`.
- Arabic font: `Noto_Naskh_Arabic` from `next/font/google`, wired into Tailwind as the `font-arabic` utility via `--font-arabic` in `app/globals.css`'s `@theme inline` block (same mechanism as the existing `font-sans`/`font-mono`).

## Data model (`supabase/schema.sql`)
- `attempts(id, user_id → auth.users, sentence_id, correct_count, total_count, created_at)` — one row per checked sentence, **per-user RLS** (`auth.uid() = user_id` on select/insert), unlike stock-tracker's shared/permissive-RLS caches — this is private progress data, not shared market data. No update/delete policy — it's an append-only log.

## Environment variables
`.env.local` (gitignored, real values already filled in by the user):
- `NEXT_PUBLIC_SUPABASE_URL` — must be the **bare project URL** (`https://<ref>.supabase.co`), not a path like `.../rest/v1/` — the `@supabase/ssr` client appends its own paths internally (`/auth/v1/...` etc.), so a pre-appended path breaks auth requests. Hit this exact mistake once already.
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

`.env.local.example` documents both (placeholders). Note `.gitignore` has `.env*` (ignore all) then `!.env.local.example` (un-ignore just that one file) so the example stays committed while real secrets don't.

## Notes for whoever picks this up
- The user is a self-described coding beginner — favor concrete, click-by-click instructions for anything outside the editor (Supabase dashboard, Google Cloud Console), same as stock-tracker.
- To add an ayah: write it with correct tashkeel (full diacritics — case endings are the whole point), work out its i'rab carefully (and check it against a real reference for anything non-obvious — this is scripture), decide which attached morphemes are worth splitting via `joined` (see the rule in the sentences.ts section above), add an entry to `SENTENCES`. Use the sentence-level `note` field for anything clause-level that doesn't fit a single word.
- To add a role: add it to `ROLES` in `lib/tarkeeb/roles.ts` with a distinct `color` (check existing ones first — 22 colors are already in use); it'll automatically appear in `RolePicker`. Roles like حال، تمييز، بدل، مفعول مطلق/لأجله/معه aren't defined yet since no current ayah needs them, not because they were rejected.
